02 / A WORKED EXAMPLE

One booking. A complete slice.

Follow an illustrative resource-booking API from intent to evidence.

ILLUSTRATIVE · SYNTHETIC DATA
THE USER OUTCOME

“I can reserve an available resource and receive a confirmation.”

A signed-in member chooses a time slot. The API confirms the reservation, enforces capacity, and handles retries predictably.

Keep the first increment focused.

Include availability, booking, capacity conflicts, and request replay. Defer payments, recurring reservations, and real notifications.

Persistent working instructions, source locations, and verified build commands.

The behavioral contract: outcome, rules, scope, and acceptance criteria.

ux.md

Interaction states and recovery paths, when the feature has a user interface.

technical-spec.md

API contracts, data model, authorization, transactions, and migration strategy.

handoff.md

Authorized scope, ordered tasks, dependencies, and verification approach.

qa-report.md

Actual test results, evidence links, defects, and remaining gaps.
